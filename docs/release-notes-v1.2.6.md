# RemoteMic v1.2.6 / 电脑端 1.1.4

本轮修正了 v1.2.5 里对**设备权限勾选**的理解错误，并补上控制权的正确规则。

## 权限语义（修正）

设置页每台设备的三个勾选框是**权限等级**，不是「总闸 + 子项」：

| 勾选 | 能做什么 |
| --- | --- |
| 勾「所有」 | 遥控 + 传文件 + 截图（全权，另两项置灰并显示为已勾） |
| 只勾「传文件」和/或「截图」 | 只有这几项能力，**没有遥控权限**，拿不到控制权 |
| 三项都不勾 | 只是连上了，没有任何权限 |

## 控制权规则（修正）

- 只有**有遥控权限**（勾了「所有」）的设备才能坐上控制位。
- 只勾传文件/截图的设备连上来不会抢控制权；当另一台有遥控权限的手机连上时，它会自动被挤到**等待状态**。
- **等待状态不影响传文件和截图**——这两件事不抢键盘焦点、不出声，只按该设备自己的权限走。
- 处于等待状态（但有遥控权限）的手机点遥控按钮，手机端明确提示 **「现在你处于等待状态，无法操作。」**
- 没有遥控权限的设备点遥控按钮，提示「权限受限，请在电脑端设置菜单授权。」
- 电脑端把正在控制的那台手机的遥控权限收回时，控制权**立刻转给下一个有遥控权限的在线设备**（没有就全员待命），被降级的手机当场收到新权限并提示。
- 托盘/手机切控制权只切给有遥控权限的设备，否则回 `switch_result {ok:false, reason:"no_perm"}`。

## 升级说明

- 老配置（只有 `receive_files`）迁移时 `perm_all` 默认 **True**，升级后仍能正常遥控，行为不变。
- 安卓 1.2.5 → 1.2.6、电脑端 1.1.3 → 1.1.4 均可**覆盖安装**，绑定关系保留（同一个签名，`6567fa4f…`）。
- 电脑端升级后需重启服务（静默安装不会自动起服务）。

## 已知限制

- 手机端目前没有「申请控制权」的主动入口，控制权切换由电脑端托盘/设置页发起；`switch_result` 回执已在协议里预留。
- 两台都**有**遥控权限的手机同时在线仍是「先连优先」，后来者进等待。
