# v1.2.0 · 稳定性与安全加固（手机端 1.2.0 + 电脑端 1.1.0）

发布日期：2026-11-21

## 下载

- **手机端**：`RemoteMic-1.2.0.apk`（Android 8.0+，约 6 MB，`versionCode=3`）
- **电脑端**：`RemoteMicSetup-1.1.0.exe`（Windows 10/11 x64，约 28 MB）

> **两端建议一起升级**。本版改了文件传输握手（手机等 `file_ack` 才推块），新手机配旧电脑端仍能工作（旧电脑端本来就回 ack），但「拒收立刻停发」「背压」等保护只有两端都升级才完整。

这一版**没有改界面布局**，全部是代码审查后的 bug 修复与安全加固，外加补齐几个早就写在文档里却没实现/没接上的显示项。

## 本版新增的显示项

- **手机端显示切换浮层状态与 Tab 序号**：电脑停在 Alt+Tab 浮层里时「切换应用」键标签变「浮层中」并高亮；切过 Tab 后「切换 Tab」键显示「Tab N」。断线自动复位。
  配套修了服务端一个真 bug：`status` 原来只在建连/断连/切控制权时广播，`mode`/`tab_index` 变了从不推送，所以这两个字段以前就算消费了也永远不更新。现在**只在它们真的变化时补一帧广播**。
- **手机端设备管理抽屉底部显示 App 版本号**（如「手机遥控麦 v1.2.0」）。
- **电脑端设置页「本机」卡片显示版本号与项目仓库链接**，点链接用系统默认浏览器打开仓库。版本号单一来源在 `remote_mic/__init__.py`，`build_installer.ps1` 打包前校验它与 `RemoteMic.iss` 的 `AppVersion` 一致，不一致直接中止。

## 电脑端 1.1.0

### 安全

- **`transfer_id` 路径穿越（高危）**：客户端传来的 `transfer_id` 未清洗就拼进 `.part_<tid>_<name>` 落盘路径，带 `../` 时可逃出接收目录**覆盖甚至删除任意文件**。现在只接受字母数字下划线连字符，不合格由服务端自生成。
- **启动应用的 `shell=True`**：改为不经 `cmd.exe`，路径里的 `&`、`^` 不再被当元字符解释。
- **PowerShell 单引号转义**：商店应用 AUMID 含 `'` 时不再破坏/注入脚本。
- **同名文件不覆盖**：原来「先 `exists()` 挑名、再 `replace()`」有竞态，且 Windows 的 `replace` 本身会覆盖目标。改为「`os.rename` 失败就试下一个候选名」，每次尝试自身原子。
- **保留名规避补全**：Windows 把首个点前的整段当设备名，`nul.a.b` 原来漏网，现在也拦。
- **声明大小校验**：收到的字节数超过 `file_begin` 声明的 size 立刻中止，防止谎报小尺寸写满磁盘。

### 稳定性

- **重连不再抢走控制权**：同一遥控器重连时，旧连接的收尾逻辑按 `remote_id` 判断身份，会把刚建好的新连接的控制权顺延给待命遥控器，并掐断它的语音。改为按**对象身份**判断；待命遥控器掉线也不再影响控制者。
- **音频锁粒度**：`stop()`/`start()` 原来持环形缓冲锁跨越 PortAudio 调用，实测 `stop()` 持锁 263 ms，期间 `feed()` 与整个 asyncio 事件循环被阻塞。现在缓冲锁与开关流生命周期锁分离。（注：审查时判断的「必现死锁」在本机 DirectSound 上**复现不了**——该 host API 排空缓冲不需要回调；改动仍是必要的，且消除了其它 host API 上的死锁隐患。）
- **阻塞调用移出事件循环**：键鼠注入、窗口置前、写剪贴板、文件分块写盘与 rename 全部改走 `asyncio.to_thread`；逐帧 `await` 保证同一连接的按键与文件块顺序不变。
- **认证路径不再跑 PowerShell**：`icon_data_url` 改为只读缓存，商店应用图标导出移到后台线程（原来可能在认证时同步阻塞数分钟）。导出失败只尝试一次，避免无限重推线程。
- **托盘菜单竞态**：状态由 asyncio 线程与托盘线程共同改写，而 pystray 在调用线程上 `DestroyMenu`/重建菜单。现在全部串行化，并把「列表+状态」合并成一次刷新。
- **客户端列表跨线程读取**统一走加锁快照。
- **配置损坏自愈**：`config.json` 解析失败时改名留证（`.corrupt`）再按默认重建，不再让 pythonw 静默闪退。
- **图标导出临时文件唯一命名**，多线程不再互删。
- **进程路径缓冲** 260 → 32768，WindowsApps 深路径不再取不到进程名（UWP 栏位匹配/发送键查表静默落空）。
- **驱动安装**：捕获安装器超时并给可读原因；非提权分支的设备轮询从 20 s 放宽到 120 s，慢机器不再误报失败。
- **奇数长 PCM 帧**截到偶数字节，不再抛异常断掉整条连接。
- **安装包**：启动服务条目加 `runasoriginaluser`，避免 UAC 用另一管理员账户授权时 config/自启落到错误 profile。

## 手机端 1.2.0

### 补齐文档承诺

- **声卡未就绪时禁用语音键**：消费 `status.audio_ready`，语音键置半透明、副标题显示「电脑声卡未就绪」，按下只提示去电脑端安装/重新探测声卡，不起录音服务；正在说话中则会话被收掉。这是 README 早就承诺、但手机端一直没实现的行为（开发计划 B1）。
- **麦克风权限降级**：补 `onRequestPermissionsResult`；权限被拒时副标题显示「无麦克风权限」，按语音键只提示不崩溃。录音服务启动失败会停掉前台服务、提示并广播给界面复位，不再出现「通知栏写着正在录音、实际一个字节没采到」。

### 文件传输

- **先握手再传**：`file_begin` 后等 `file_ack`（10 s 超时）才推块；收到 `file_reject` 立刻停发并提示。原来拒收后仍会把整个文件白推一遍并计入「发送完成」。
- **发送背压**：OkHttp 待发送队列超 2 MB 就等回落，持续 30 s 不回落判停滞中止，避免大文件在弱网/慢盘时堆到 OOM。
- **文件大小取值修正**：原来用 `InputStream.available()` 当总长（它只是「当前不阻塞可读字节数」），provider 不给 SIZE 时会拿到 0 或残值，导致电脑端大小校验失败而手机已报「发送完成」。改用 `openFileDescriptor().statSize`，拿不到再完整读一遍计数。
- **接收取消会通知电脑端**：原来只清本地，电脑端继续把整个文件推完并报成功。
- **接收文件名清洗**：电脑端 `file_offer` 的名字原来直接当路径用，`../` 可写出下载目录；现在与电脑端同规则清洗。
- **Android 8/9 接收**：未授予 `WRITE_EXTERNAL_STORAGE` 时明确拒收并提示，不再静默失败。

### 安全与隐私

- **日志脱敏**：不再打印每一帧全文（截屏 base64 数百 KB、apps 帧带 4 个图标），只打 type 与长度；扫码页不再把含绑定 token 的二维码内容写进 logcat。
- **`allowBackup=false`**：绑定 token 明文存 SharedPreferences，不再随系统自动备份上云/被 adb 导出。
- **二维码 host/port 校验**：host 含 `/`、`@` 等字符时 `ws://$host:$port` 会被解析成别的主机/端口（恶意二维码可把手机引到攻击者机器）。现在只放行 IPv4/主机名字符集，端口必须 1..65535。

### 生命周期

- **OkHttpClient 全进程复用**：原来每次切换设备都新建一个（各自带线程池与连接池且不释放），反复切换会累积线程。
- **跨线程字段加 `@Volatile`**：`ws`/`stopped` 等在 OkHttp 回调线程与主线程间读写，身份判重可能读到旧值。
- **设备抽屉不再叠加**：认证失败重弹时先收掉旧的；旧抽屉的迟到 dismiss 回调不会清掉新抽屉的列表刷新函数。
- **`onDestroy` 清理补全**：收掉下拉/抽屉/进度浮窗（窗口泄漏）、清 `uiHandler` 延迟回调、停录音服务。传输前台服务的「必须满 6 秒才能停」约束保留，未到点的停止改用 applicationContext 重排，回调不再持有已销毁的 Activity。
- **截屏单飞 + 状态检查**：连点不再起多个解码线程互相覆盖 Bitmap；界面非 RESUMED 或已销毁时丢帧并回收 Bitmap，不再崩溃/泄漏。

## 安装与升级

- APK 仍使用本机 **debug 签名**（与 1.1.0 及开发版同签名，SHA-256 `90f6d87b…`），**直接覆盖安装，绑定不丢**。公开分发/上架前必须换独立 release keystore（换签名后需卸载重装）。
- 电脑端安装包未签名，SmartScreen 首次运行提示「未知发布者」属预期。
- 电脑端升级不覆盖 `%LOCALAPPDATA%\RemoteMic\config.json`。

## 验证

在一加 13 / ColorOS 17（PJZ110）+ Windows 11 真机上实测：

- **91 MB 视频传输两端 MD5 完全一致**（`bfaa35ee7df6d600236e4411cf2c67aa`，95,227,452 字节），4 秒传完，传输期间手机 PSS 129→117 MB 无增长。
- **拒收路径**：把接收目录临时指向不可写位置 → 电脑端 `file_reject` → 手机 0.8 秒内弹错误提示、**零数据块上传**、界面立即回到主屏。
- **双遥控器控制权**：A 重连顶掉旧连接后 `active_id` 仍在 A 手上，B 保持待命；B 掉线不影响 A。
- **声卡未就绪**：把 `audio_device_keyword` 改成不存在的设备 → 手机副标题变「电脑声卡未就绪」，点语音键**不起录音服务、通知栏无录音**；改回后无需重启 App 即恢复「双击常开」。
- **真实 VB-CABLE 声卡** 5 轮 `stop()/start()` 全部正常，`feed()` 零阻塞。
- `transfer_id` 穿越用例（`../`、绝对路径、反斜杠、超长、空）全部拦在接收目录内；并发同名传输不互相覆盖。
- 打包产物验证：`RemoteMicSetup-1.1.0.exe` 编译成功；**用打包后的 exe（而非源码）+ release APK 组合**再跑一次传输，成功、无崩溃、无 `.part` 残留。
- **浮层/Tab 显示**：真机点「切换应用」→ 标签变「浮层中」；点「取消」→ 恢复；点「切换 Tab」两次 → 「Tab 1」「Tab 2」。
- **设备管理版本号**：抽屉底部显示「手机遥控麦 v1.2.0」。
- **设置页版本/仓库**：把真实 HTML 配真实 state 渲染验证，「电脑端版本 v1.1.0」「项目仓库」链接正确显示，点击触发 `open_repo` bridge 无报错。
- `assembleRelease` 通过；`apksigner` 签名与旧版一致；`aapt` 确认 `versionName=1.2.0`、`versionCode=3`。

## 已知限制 / 本轮未做

- **设置页配置读改写仍无跨线程锁**：`set_slot_app` 只改内存，而改接收目录等操作会从磁盘重读再写回，未保存的栏位选择可能被冲掉。改动涉及设置页保存流程，回归风险偏高，留待下一轮。
- **接收侧 MediaStore 操作仍在主线程**：大文件收尾可能卡顿。
- **传输前台服务停止时机分散在两处**（Service 自身 `stopSelf` 与 Activity 的 6 秒延迟），6 秒内开下一轮传输可能不重启前台服务。
- **托盘菜单跨线程 GDI**：已串行化消除并发竞态，但完整的「marshal 到托盘线程」需要改 pystray 内部实现，本轮未做。
- 文件互传仍无断点续传；单文件 ≤ 2 GB、一次 ≤ 50 个；不做会话总量控制。
- 音频仍是 16 kHz/16 bit/单声道未压缩 PCM，未上 Opus。
- 不做后台常驻保活，熄屏断连属预期。

## 一个尚未定位的观察

调试前发现服务日志里有 **255 次重连、每次会话恰好 20.0 秒**，手机侧报 `sent ping but didn't receive pong within 10000ms (after 0 successful ping/pongs)`，同时存在 3 条 ESTABLISHED 连接。用独立客户端探针测同一服务，pong RTT 0.4~1 ms，**电脑端健康**。`force-stop` 重启 App 后风暴消失，之后出现 331 秒稳定会话。

现象像是多个存活的 `RemoteWsClient` 实例用同一 token 互相顶替。本轮的 OkHttp 复用与 `@Volatile` 改动可能相关，但**没有根因确认**，需要后续观察能否复现。
