# v1.2.5 · 设备权限三档（所有 / 传文件 / 截图）+ 放开控制权限制

发布日期：2026-11-21

## 下载

- **手机端**：`RemoteMic-1.2.5.apk`（Android 8.0+，约 6 MB，`versionCode=8`）
- **电脑端**：`RemoteMicSetup-1.1.3.exe`（Windows 10/11 x64，约 27 MB）

## 为什么要改

1. 只有一台遥控器能"传文件"，是因为设置页里每台设备只有一个「接收文件」勾选，颗粒度不够——想放开截图却不想放开传文件时没法表达。
2. 两台遥控器同连一台电脑时，**处于「等待控制权」的那台既不能传文件也不能截屏**：`file_begin` / `screenshot` 都在 `_on_control()` 的控制权闸门后面被静默丢弃，手机端表现为"点了没反应 / 提示未连接"。

## 改了什么

### 1. 设备权限从 1 档变 3 档

设置页「已绑定设备」列表新增三列勾选：**所有 / 传文件 / 截图**。

- 勾「所有」时另两项置灰、显示为已勾；取消「所有」后可以单独勾一项、两项，或者都不勾。
- 存储层对应 `perm_all` / `perm_files` / `perm_shot` 三个字段（`config.json`）；`receive_files` 仍按 `perm_files or perm_shot` 回写，旧版电脑端不受影响。
- 老配置（只有 `receive_files`）启动时自动迁移成两个子权限都取原值，**升级后行为不变**。

### 2. 权限变更实时推送 + 重连带最新

- 设置页改动后 `reload_config()` 会比对每一条在线连接的缓存权限，变了就推 `{"type":"perms","files":…,"screenshot":…}`，**不论该连接是否持有控制权**（待命中的手机也立即更新）。
- `auth_ok` 里同时下发 `perms{files,screenshot}`，并保留旧字段 `files_allowed` 兼容旧版手机端。
- 手机端收到后更新按钮可用性，并弹一条「电脑端权限已更新：传文件可用，截图已禁止」。

### 3. 没权限时直接提示，不再干等

手机端点「截屏」/「照片」/「文件」时先本地判断权限，没有就提示**「权限受限，请在电脑端设置菜单授权。」**，不发请求、不等 10 秒超时。电脑端也做了兜底：`_handle_screenshot` 无权限直接回 `{ok:false, reason:"perm_denied"}`。

### 4. 待命状态也能传文件、截屏、请求接管

`_on_control()` 的控制权闸门改为只拦**控制类**消息（`key` / `send` / `voice` / `voice_toggle` / `launch` / `switcher` / `clip` / `mic`）。以下改为待命也放行（`STANDBY_ALLOWED_TYPES`）：

- `screenshot`、`file_begin` / `file_end` / `file_abort` / `file_accept`——不抢键盘焦点、不出声；
- `switch_active`——待命方本来就应该能自己申请接管（此前被闸门拦住，只能靠电脑端托盘切换）。

## 验证

| 场景 | 结果 |
|---|---|
| 设置页三勾选渲染与置灰 | 通过（三台设备：全权 / 仅传文件 / 无权限，渲染正确） |
| 老配置迁移 | 通过（`receive_files=True` → 两个子权限均 True） |
| 权限落盘组合（全开 / 全关 / 仅文件 / 仅截图 / 非法 id） | 通过（`remote_perms` 返回值与字段全部符合预期） |
| 推送：改权限 → 变化的两条连接各推一帧、未变不重复推 | 通过（单测覆盖 `reload_config`） |
| 闸门：待命发 `screenshot` / `file_begin` / `switch_active` 放行，`key` 仍拦 | 通过 |
| 真机：电脑端关掉截图权限 → 手机重连 → 点截屏 | 提示「权限受限，请在电脑端设置菜单授权。」，电脑端日志无请求 |
| 真机：电脑端恢复「所有」 → 手机点截屏 | 正常出图（`screenshot sent: 1600x900, 94 KB`） |
| 真机：有文件权限时点「照片」 | 系统 Photo Picker 正常打开 |

> 双机同连场景本机只有一台遥控器绑定，未做双机实测；结论来自代码路径 + 闸门单测。

## 升级方式

覆盖安装即可，同 release 签名，绑定与 token 保留。存量 `config.json` 会在服务下次启动时自动补上权限字段，无需手工改。

## 已知限制

- 双机同时往同一目录传同名文件仍靠"自动加 `(1)`"避让，没做互斥锁。
- 权限只区分"能不能传文件/截图"，不区分目标目录或内容类型。
