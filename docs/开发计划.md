## 一、背景与基线

### 1.1 一期（M1 + M2）已落地并真机通过

- **链路**：手机（一加 13 / ColorOS 17）经同一 WiFi 连电脑 Python 服务，WebSocket `0.0.0.0:8765`，连接稳定。
- **按键控制**：方向键 ↑↓←→、确认 Enter、退格 Backspace、音量 ±、媒体上一首/下一首/播放暂停、滚轮上下滑动、Alt-Tab 会话、选区复制/粘贴、三栏位（豆包 / Chrome / 抖音）往返聚焦与窗口尺寸保持，均已实测正常。
- **语音推流**：手机 `AudioRecord` 采集 16k/16bit/单声道 PCM，20ms/帧推到电脑，写入 VB-CABLE `CABLE Input`；微信输入法从 `CABLE Output` 拾音上屏，无明显卡顿变调。
- **电脑端形态**：独立 Python 进程 + 系统托盘；手动启动，不开机自启；断线兜底释放修饰键。

### 1.2 一期已知边界（含 2026-11-20 回填的现状）

| 边界 | 现状 |
| --- | --- |
| 音频为未压缩 PCM，带宽/延迟不达标时再上 Opus 等压缩 | **仍如此**（16k/16bit/mono ≈ 256 kbps）。局域网够用，未做压缩（见 §5 P5.3） |
| 局域网自用，未做鉴权；协议已预留 token 字段 | **已解决**：首帧 `auth{token}` + `auth_fail`，token 按遥控器签发，删绑定即失效 |
| 应用栏位靠手填 `config.json` 绝对路径；无应用图标下发 | **已解决**：设置页点选枚举（42 项全有图标）+ 图标 256px 下发到手机 |
| 后台保活未做强；断线/重连后手机端 UI 与服务端状态可能不一致 | **已按新口径解决**：不做后台保活，改 `wakeUp()` 亮屏/解锁/回界面即刻探活重连（实测 0.3 s） |
| 复制粘贴依赖"选区模式"状态机，进入后方向键变为 Shift+方向 | **已改**：2026-11-20 选区模式整条删除，改为「远程粘贴」（`clip`） |
| 手动启动、不开机自启 | **已变**：托盘「开机自动启动」勾选（HKCU Run，默认不勾）；安装包可选开机自启 |

### 1.3 二期第一批已落地（2026-11-19）

**触发原因：手工实测推翻了原"自研手势范式"的方向。** 实测结论：

| 实测项 | 结果 |
| --- | --- |
| 绝大多数视频类软件、Chrome 内的视频网站 | 方向键 **↑↓ 切视频**、**←→ 拖进度**、**空格 播放/暂停** 全部可用 |
| 手机 App 现有上下左右按键 | 直接驱动上述行为，已验证可行 |
| Alt-Tab 切换浮层 | 用**方向键**即可遍历窗口，不需要独立的左右键 |
| 复制粘贴 | 已改为**远程粘贴**（2026-11-20）：用户在手机上自行复制 → 点一次「远程粘贴」→ 电脑端写入剪贴板（前台有文本光标时补 Ctrl+V） |

**结论：不需要三段式手势、触摸板、滑动音量条；直接映射标准键盘，行为最稳、也最通用。** 二期输入模型据此收敛。

#### 1.3.3 语音键语义（原"常开"开关已删除）

- **按住**：临时说话，松手停止（松手后延时 320ms 才真正停，给双击留窗口）。
- **快速双击**：进入常开（不中断录音，取消即将执行的停止）。
- **常开态单击**：结束说话并退出常开。
- 按钮文字实时反映状态：`按住说话·双击常开` → `说话中…` → `点击结束`。

#### 1.3.5 过程中修掉的两个问题（记入经验）

1. `server.py` 分发未登记 `send` 类型，导致"发送"报 `unknown message type`；新增消息类型必须同步登记分发。
2. Kotlin 增量编译缓存损坏会产生整片 `Unresolved reference: click/press/hold` 假错误；遇"代码没动却全红"直接 `clean assembleDebug`。

### 1.4 二期第二批已落地（2026-11-19 晚）

#### 1.4.1 电脑端：多遥控器 + 扫码绑定

- **配置文件新增字段**：`computer_name`（默认取主机名）、`remotes[]`（`id / name / token / added / last_ip / last_seen`）、`slot_send_hotkey{}`（栏位级发送键）。
- **认证**：首帧必须 `{"type":"auth","token":…,"device":…}`；token 不在 `remotes` 内即回 `auth_fail{reason}` 并断开。删除绑定后 token 立刻失效。
  - 已知代价：**旧版 App（无 token）将被拒绝**，必须与本版 App 同步上线。
- **多遥控器与控制权**：允许多台同时连上，**先连上的优先拿到控制权**；待命端按键被忽略并记日志（`ignored … from standby remote`）；控制端断线后控制权**顺延**给最早连上的待命端。
- **托盘**：新增「切换控制遥控器」子菜单（● 当前 / ○ 待命），可鼠标右键直接切换；新增「设置…」入口；图标颜色反映状态（绿=控制中、黄=有连接但无控制权、灰=无连接）。
- **设置页**（pywebview 弹窗，内嵌本地 HTML，仿 Windows「应用和功能」样式）：
  - 本机信息：电脑名称（可改）、局域网地址、端口；
  - 「已绑定遥控器」列表（名称 / 上次 IP / 绑定时间 / 状态）＋ 删除按钮（删除即断开并让 token 失效）；
  - **生成绑定二维码**：payload 为紧凑 JSON `{"t":"remote-mic","name":<电脑名>,"host":<局域网IP>,"port":…,"token":…}`，二维码旁印出电脑名与 IP；
  - **四栏位配置**：不填绝对路径，改为「选择应用」弹层挑选；**发送键为下拉选择**（无 / enter / ctrl+enter），不再手工输入。
  - 应用列表按 Windows 应用管理样式展示：图标、名称、发布者、版本、安装时间、大小；已排除卸载程序与系统组件。
- **进程模型调整**：pywebview 只能跑主线程，而主线程原本被托盘占用 → 托盘改为 `run_detached()` 后台线程，主线程专门承接"打开设置窗口"的请求队列；asyncio 服务仍在独立线程。
- **已装应用枚举**：注册表 Uninstall（HKLM 64/32 + HKCU）＋ 开始菜单 `.lnk` 解析（覆盖绿色版/便携版）＋ **商店应用（UWP，`uwp:<AUMID>`）**；排除 Windows 目录内系统程序与卸载项。本机实测枚举出 **69 项**（后续按"应用和功能"口径收敛为 42 项）。
  - UWP 启动走 `explorer.exe shell:AppsFolder\<AUMID>`（`actioner.handle_launch` 已支持 `uwp:` 前缀）。
  - 绿色版仍保留「浏览 exe…」作为兜底（即思路笔记里的"自定义"）。
- **发送键优先级**（`handle_send`）：栏位自定义 `slot_send_hotkey` → `send_hotkey[前台exe]` → `default`（Enter）。

#### 1.4.2 手机端：设备绑定页

- 顶栏新增可点击的**设备入口**，显示"设备名 · 已连接 / 待命（控制权在其他遥控器）/ 未连接"，左侧小圆点绿/黄/灰对应三态。
- 点击进入**设备绑定页**：已绑定电脑列表（● 当前）、逐条删除、扫码绑定设备（唯一入口；早期的手动输入 IP / token 兜底已在 1.0.4 前移除，避免手填地址覆盖已连设备）。
- 扫码：**2026-11-20 已换掉 `zxing-android-embedded`**，改为 CameraX + `zxing-core` 自建竖屏扫码页（`scan/QrScanActivity.kt`，无横屏 Activity 依赖），识别 `{"t":"remote-mic",…}` 后自动入库并立刻连接；token 随设备持久化（`SharedPreferences`）。
- 认证失败（token 已被删除）→ 提示"认证失败，请重新扫码绑定"，并直接弹出绑定页。
- 多电脑：仅一台时自动连接；多台时按上次选择/列表挑选（`current_token` 记忆）。
- **明确不做**：后台保活、常驻通知栏（与用户约定一致；录音前台服务通知仅在录音期间出现）。

## 二、规划原则（修订）

1. **能用标准键盘解决的，就不自研手势。** 实测优先：先用手上按键驱动通用软件，证实可行即采用；只有键盘不可达的动作（如物理音量键、连续音量）才考虑自研。
2. **不破坏已验收行为**：改动在现有可用基线上增量演进。
3. **一次只演进一类**：键位模型、绑定认证、打包配置、扩展场景分阶段推进，互不阻塞。
4. **协议先行**：新增消息类型先在协议层定义并同步登记分发，再落两端。
5. **自用优先**：鉴权、打包、多设备按自用场景做最小可用实现。
6. **（2026-11-20 新增）先能装、能用，再谈增强**：v1.0.0 起交付物以安装包为唯一形态，任何新功能都必须能在安装版上跑通，禁止只在仓库脚本态可用。
7. **（2026-11-20 新增）运行期数据不落程序目录**：`config.json` / 日志 / 图标缓存一律在 `%LOCALAPPDATA%\RemoteMic\`，程序目录只读（Program Files 不可写）。

| `apps` | `slots[{slot,name,icon}]` | 四栏位名称 + 256 px 图标（`data:` URL），连接后推 + 缺图标补推 |
| `screenshot` | `ok`, `w`, `h`, `bytes`, `image` / `reason` | 截屏结果（JPEG base64，不落盘） |
| `files_allowed` | `allow` | 该遥控器是否允许传文件 |
| `file_ack` / `file_reject` | `transfer_id`, `reason` | 接收就绪 / 拒绝（开关关闭、超数量、超大小、非法名） |

| `file_offer` | `transfer_id`, `name`, `size`, `index`, `count` | 电脑请求发给手机 |
| `file_end` | `transfer_id`, `ok` | 反向传输结束回执 |

## 十、代码审查与加固轮（v1.2.0 / 电脑端 1.1.0，2026-11-21）

对全部源码做了一次审查，按严重度修完 🔴 与大部分 🟡，明细见 [v1.2.0 发布说明](release-notes-v1.2.0.md)。这里只记**结论性口径**与**留给下一轮的项**。

### 10.1 审查中被修正的判断

| 原判断 | 真机复核结论 |
| --- | --- |
| `AudioOut.stop()` 持锁关流 → **必现死锁**（🔴） | **本机 DirectSound 上复现不了**：实测旧 `stop()` 耗时 263 ms、期间回调被调用 **0 次**，说明该 host API 排空缓冲不需要回调，不会与回调互等。真实问题是**持缓冲锁 263 ms 阻塞 `feed()` 与整个事件循环**。锁粒度改动仍然必要（也消除其它 host API 的死锁隐患），但严重度降为 🟡 |
| 手机端 `onText` 没有 `file_reject` 分支 | 实际有，但只发进度不通知发送线程停发；且 `file_ack` **根本没被 MainActivity 路由**到 FileTransferManager。已一并修 |

### 10.2 本轮明确不做（回归风险偏高，留下一轮）

| # | 事项 | 为什么留 |
| --- | --- | --- |
| D1 | **设置页配置读改写加锁** | `set_slot_app` 只改内存，`choose_dir`/`reset_dir`/`set_remote_files` 从磁盘重读再写回 → 未保存的栏位选择会被静默冲掉。修它要动整个设置页保存流程，需配套回归 |
| D2 | **接收侧 MediaStore 移出主线程** | insert/open/flush/close 目前在主线程（文本帧经主线程分发），大文件收尾卡顿。要改分发线程模型，影响面广 |
| D3 | **传输前台服务停止时机收敛** | Service 自身 `stopSelf` 与 Activity 的 6 秒延迟停并存，6 秒内开下一轮可能不重启前台服务。涉及「startForegroundService 后 5 s 内必须进前台」的系统约束，改错会被系统杀进程 |
| D4 | **托盘菜单 marshal 到托盘线程** | 已用锁串行化消除并发 GDI 竞态；完整修复需改 pystray 内部消息循环，属侵入式改动 |
| D5 | ~~`status.mode` / `tab_index` 手机端消费~~ | ✅ **已做（v1.2.0）**：「切换应用」键在浮层中显示「浮层中」并高亮，「切换 Tab」键显示「Tab N」；断线复位。同时修了服务端**只在 mode/tab_index 变化时补广播 status**（原来只在建连/断连/切控制权时发，字段永远不更新） |

### 10.3 尚未定位的观察：重连风暴

调试前实测到 **255 次重连、每次会话恰好 20.0 s**，手机侧 `sent ping but didn't receive pong within 10000ms (after 0 successful ping/pongs)`，netstat 同时 3 条 ESTABLISHED。独立 Python 客户端探针测同一服务 pong RTT 0.4~1 ms（**电脑端健康**）；`force-stop` 重启 App 后风暴消失，随后出现 331 s 稳定会话。

推测是多个存活的 `RemoteWsClient` 实例用同一 token 互相顶替（每条新连接都触发 `replace stale connection`，旧 socket 还没完成一次 ping/pong 就被换掉）。本轮的 OkHttpClient 复用与 `@Volatile` 可能相关，但**未根因确认**。

复现线索：长时间运行 + 反复亮屏/解锁（`wakeUp()` 路径）+ 切换设备。下次出现时先抓 `adb logcat --pid=<app>` 里 `ws open` / `ws failure` 的**线程号与时间间隔**，并数 netstat 的 ESTABLISHED 条数。
