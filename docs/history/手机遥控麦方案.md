# Android 手机遥控麦方案（手机 App → 电脑）设计

立项日期：2026-11-14
方向：**彻底抛弃老款蓝牙遥控器**，用 Android 手机 App 直接作为电脑的遥控器 + 无线麦克风，电脑端由独立轻量 Python 服务接收并落地为按键模拟与虚拟麦克风输入。

> 本文档是新主线设计；遥控器侧调研存档见 `可行性评估.md`。

---

## 一、目标与范围

### 1.1 要做什么

- 手机触屏按键 → 局域网发到电脑 → 电脑模拟键盘 / 快捷键 / 媒体键 / 鼠标滚轮 / 启动应用。
- 手机麦克风录音 → 实时推流到电脑 → 写入虚拟声卡 → 微信输入法从虚拟麦克风拾音出字。
- 语音支持两种触发：**按住说话**（push-to-talk）和**点按常开**（toggle，长音频场景）。

### 1.2 明确不做什么

- 不再连接、不再逆向那台小米老款遥控器；不依赖其 BLE / 私有协议。
- 不做手机端本地语音识别上屏；语音以**音频流**形式传给电脑，识别交给电脑上的输入法。
- 第一版不做音频压缩（先发 PCM），Opus 等压缩作为二期优化。
- **不做单击 / 双击 / 长按三档区分**（SayAll 那套是迁就遥控器按键的设计）；手机端每个按钮只有按下 / 松开两个事件。
- 电脑端**不做开机自启**；服务手动启动，常驻系统托盘。

### 1.3 已确认的取向

| 项 | 选择 |
| --- | --- |
| 手机平台 / 机型 | Android，**一加 13，ColorOS 17** |
| 电脑端实现 | 独立轻量 Python 服务（不基于 SayAll Rust 仓库） |
| 手机 ↔ 电脑通道 | 局域网 WiFi / 热点，WebSocket（免配对、无 RFCOMM 驱动、带宽足） |
| 电脑端形态 | 后台服务 + 右下角系统托盘图标；不开机自启 |
| 后台保活 | 不做强保活：使用时 App 在前台；进程被杀后下次启动自动重连即可 |
| 语音交互 | 按住说话 + 点按常开两种；快捷键 **Ctrl+Win 写死**，不做配置项 |
| 应用栏位 | 最多 **4 个**，在配置文件里填应用绝对路径 |
| 滚动方向 | 与手机抖音一致：**上滑看下一个，下滑看上一个** |

## 二、总体架构

```
┌─────────────────────────────┐            局域网 WebSocket             ┌──────────────────────────────────┐
│          Android App         │  ws://<电脑IP>:<端口>                   │         电脑 Python 服务          │
│                              │  ── 按键 / 指令 JSON 文本帧 ─────────▶ │  ├─ WebSocket 服务端（分发消息）   │
│  ├─ 大屏按键布局 UI          │  ◀── 状态 / 错误 文本帧 ─────────────  │  ├─ 动作执行器（键盘/媒体/滚轮/  │
│  ├─ AudioRecord 麦克风采集   │  ── PCM 二进制音频帧 ────────────────▶  │  │   应用启动 / Alt-Tab / 选区）  │
│  ├─ WebSocket 客户端 + 重连  │                                        │  ├─ 环形缓冲 → sounddevice 写声卡 │
│  └─ 录音前台服务（仅录音时） │                                        │  └─ 系统托盘图标 + 配置检测       │
└─────────────────────────────┘                                        │        │                        │
                                                                       │  VB-CABLE Input (虚拟声卡)  │
                                                                       │        │ CABLE Output         │
                                                                       │        ▼                        │
                                                                       │  微信输入法拾音出字          │
                                                                       └──────────────────────────────────┘
```

数据流分两类：
- **控制面**：JSON 文本帧（按键、应用启动、Alt-Tab 会话、选区模式、麦克风开关、心跳、状态）。
- **音频面**：二进制 PCM 帧，由语音键 / mic 启停界定区间。

## 三、通信协议（手机 → 电脑）

### 3.1 连接

- 协议：WebSocket（ws），电脑监听 `0.0.0.0:<端口>`（默认 `8765`）。
- 寻址：第一版在手机配置页手动填电脑 IP + 端口；自动发现（mDNS / 广播）二期再做。
- 鉴权：第一版局域网自用，不做鉴权；预留一个简单 token 字段。
- 重连：手机端断线后自动重连；重连成功后重发 `hello`。

### 3.2 控制消息（JSON 文本帧）

| 方向 | type | 字段 | 说明 |
| --- | --- | --- | --- |
| 手机→电脑 | `hello` | `device`, `app_version`, `ts` | 连接后首帧握手 |
| 手机→电脑 | `key` | `code`, `action: down/up` | 普通按键按下 / 松开 |
| 手机→电脑 | `voice` | `action: down/up` | 语音键按住 / 松开（push-to-talk） |
| 手机→电脑 | `voice_toggle` | `action: on/off` | 语音常开开关，点按翻转 |
| 手机→电脑 | `launch` | `slot: 1/2/3/4` | 启动对应栏位绑定的应用 |
| 手机→电脑 | `switcher` | `action: enter/next/prev/confirm/cancel` | Alt-Tab 窗口切换会话（见 3.6） |
| 手机→电脑 | `select` | `action: enter/exit` | 进入 / 退出文本选择模式（见 3.5） |
| 手机→电脑 | `mic` | `action: start/stop` | 开始 / 停止推音频流（一般由语音编排，也可单独发） |
| 手机→电脑 | `ping` | `ts` | 心跳 |
| 电脑→手机 | `pong` | `ts` | 心跳应答 |
| 电脑→手机 | `status` | `state`, `message` | 连接 / 声卡 / 错误状态回传 |

### 3.3 按键码与电脑端动作映射

动作在电脑端执行器内固化，手机端只发语义码。第一版映射如下：

| 分组 | 手机端 code | 电脑端动作 | 实现方式 |
| --- | --- | --- | --- |
| 方向导航 | `up` / `down` / `left` / `right` | 方向键 ↑↓←→（选择模式内为 Shift+方向，见 3.5） | pynput 方向键 |
| 确认 | `ok` | Enter（选择模式内为 Ctrl+C 复制） | pynput 回车 / 组合键 |
| 删除 | `delete` | Delete 键 | pynput Delete |
| 语音 | `voice`（复合） | 按住：按 Ctrl+Win + 开始推麦；松开：停麦 + 释放 Ctrl+Win | 组合键 + mic 编排 |
| 语音常开 | `voice_toggle` | 点按翻转：on 按 Ctrl+Win + 收麦；off 停麦 + 释放 Ctrl+Win | 状态机 + mic 编排 |
| 应用启动 | `launch` slot 1~4 | 启动配置里对应绝对路径的应用 | `os.startfile` / 进程启动 |
| 编辑 | `paste` | Ctrl + V | 组合键 |
| 窗口切换 | `switcher` | Alt-Tab 会话（见 3.6） | 状态机 + 组合键 |
| 媒体 | `prev_track` | 上一首 | 媒体键 MediaPreviousTrack |
| 媒体 | `next_track` | 下一首 | 媒体键 MediaNextTrack |
| 媒体 | `play_pause` | 播放 / 暂停 | 媒体键 MediaPlayPause |
| 媒体 | `vol_up` | 音量 + | 媒体键 VolumeUp |
| 媒体 | `vol_down` | 音量 − | 媒体键 VolumeDown |
| 滚动 | `scroll_next` | 上滑 → 看下一个视频 → 鼠标滚轮向下 | pynput 滚轮 |
| 滚动 | `scroll_prev` | 下滑 → 看上一个视频 → 鼠标滚轮向上 | pynput 滚轮 |

> 复制不做裸 Ctrl+C：必须先进入选择模式、用方向键选区，确认后才复制（见 3.5）。
> 滚轮方向以手机抖音习惯为准；实际在电脑版抖音 / 网页端表现若相反，再在执行器里对调方向。

### 3.4 语音编排（按住 + 常开）

电脑端维护一个麦克风状态：`off / on`。

**按住（push-to-talk）**
- `voice down`：若当前为 off → 按 Ctrl+Win、开始收麦，状态置 on。
- `voice up`：停止收麦、释放 Ctrl+Win，状态置 off。

**常开（toggle）**
- `voice_toggle on`：若 off → 按 Ctrl+Win、开始收麦，状态置 on。
- `voice_toggle off`：停止收麦、释放 Ctrl+Win，状态置 off。

两种方式互斥：任一途径进入 on 后，另一种途径的停止动作都能把状态复位到 off；快捷键与麦同生同灭，避免"麦在录但输入法没激活"或反之。Ctrl+Win 写死，不做配置项。

### 3.5 文本选择与复制流程

裸 Ctrl+C 在没选中文字时没有意义，因此复制走一套选区流程，电脑端维护 `普通 / 选择` 模式：

| 模式 | 收到动作 | 行为 |
| --- | --- | --- |
| 普通 | `select enter` | 进入选择模式 |
| 选择 | `up/down/left/right` | Shift + 方向键，扩展 / 调整选区 |
| 选择 | `ok` | Ctrl+C 复制当前选区 → 退出选择模式 |
| 选择 | `select exit`（或返回键） | 退出选择模式，不复制 |

手机端"复制"按钮点按即发 `select enter`；进入选择态后界面给出提示，方向键用于选区，确认键复制，返回键取消。删除键 `delete` 在普通模式直接发 Delete。

### 3.6 Alt-Tab 窗口切换会话

需求：一键进入任务选择界面并持续停留，继续按方向顺序选择后台软件，确认键切换到选中窗口。电脑端维护切换会话状态机：

| 状态 | 收到动作 | 行为 |
| --- | --- | --- |
| `idle` | `switcher enter` | 按住 Alt，按一次 Tab 打开任务切换视图 → 进入 `active` |
| `active` | `switcher next` | 再按一次 Tab，向后循环选择 |
| `active` | `switcher prev` | Shift + Tab，向前循环选择 |
| `active` | `switcher confirm` | 松开 Alt，切换到当前选中窗口 → 回到 `idle` |
| `active` | `switcher cancel` | 松开 Alt，不切换 → 回到 `idle` |

手机端进入切换态后，方向键复用为 `next/prev`；确认键发 `confirm`，返回键发 `cancel`。

### 3.7 音频帧（二进制帧）

第一版固定格式，双方对齐：

| 项 | 值 |
| --- | --- |
| 采样率 | 16000 Hz |
| 采样格式 | 16-bit 有符号 PCM，小端序 |
| 声道 | 单声道 |
| 帧长 | 20 ms = 320 采样 = 640 字节 / 帧 |
| 区间 | 语音 on / `mic start` 之后持续发送，语音 off / `mic stop` 停止 |

二进制帧不带包头（格式固定）；后续若加 Opus 压缩或多格式，再在 `mic start` 里带编码/采样率协商字段。

## 四、电脑端模块（Python，独立进程）

### 4.1 模块划分

| 文件（规划） | 职责 | 关键依赖 |
| --- | --- | --- |
| `server.py` | WebSocket 服务端，接受手机连接，按帧类型分发；维护连接与心跳 | `websockets` |
| `actioner.py` | 动作执行器：键盘 / 组合键 / 媒体键 / 鼠标滚轮 / 应用启动 / Alt-Tab 会话 / 选区模式 / 语音状态机 | `pynput` |
| `audio_out.py` | 环形缓冲 + 音频输出，定位 CABLE Input 设备，写 PCM | `sounddevice`、`numpy` |
| `tray.py` | 系统托盘图标：连接状态、声卡选择、退出菜单 | `pystray`、`Pillow` |
| `config.json` | 端口、采样率、目标声卡关键字、4 个应用栏位绝对路径 | — |

### 4.2 关键设计

- **独立进程运行**：Python 服务作为独立后台进程启动，不由豆包或其他前台应用派生；**不开机自启**，需要时手动启动。
- **系统托盘**：右下角托盘图标显示连接状态（已连接/未连接、声卡是否就绪）；右键菜单含"刷新声卡设备 / 打开配置 / 退出"。
- **声卡选择**：启动时枚举输出设备，按名称关键字 `CABLE Input` / `VB-Audio Virtual Cable` 匹配；找不到则托盘与 `status` 明确提示，不崩溃。
- **音频缓冲**：环形缓冲隔离网络抖动与播放节奏；溢出丢旧帧、欠载补静音，避免堆积延迟。
- **状态机兜底**：Alt-Tab 会话、选区模式、语音 on/off 都在执行器内维护；断线、异常、退出时兜底释放 Alt / Shift / Ctrl / Win 等修饰键，避免按键卡住。
- **应用启动**：4 个栏位在配置文件填可执行绝对路径；`launch` 到来时启动对应程序，失败在托盘与 `status` 回传提示。
- **进程边界**：WebSocket 收发、音频播放、动作注入分线程/协程，避免相互阻塞。

### 4.3 环境前置（电脑）

- 已装：Python 3.13.18（`python` 可用；`pip` 不在 PATH，用 `python -m pip`）。
- 待装依赖：`websockets`、`sounddevice`、`pynput`、`numpy`、`pystray`、`Pillow`。
- 待装：**VB-CABLE** 虚拟声卡（当前机器未安装，音频设备仅 High Definition Audio）。
- 防火墙：放行 Python 监听端口；手机电脑同网段，关闭路由器 AP 隔离。

## 五、手机端模块（Android / Kotlin，规划）

### 5.1 界面布局（大屏、简洁，无三档手势）

参考 SayAll 界面分区，但去掉单击/双击/长按，充分利用手机屏幕：

- **顶栏**：连接状态指示灯 + 设置入口（电脑 IP / 端口）。
- **方向圆盘**：上 / 下 / 左 / 右 + 中心确认键。
- **语音区**：语音大按钮（按住说话）+ 旁边一个**常开开关**（点按开始、再点按停止，长音频场景）。
- **应用栏**：最多 **4 个**可配置应用快捷按钮（栏位名对应配置文件路径）。
- **编辑行**：复制（进入选区模式）、粘贴、删除。
- **窗口切换**：Alt-Tab 按钮；进入切换态后用方向键选择、确认键切换、返回取消。
- **媒体行**：上一首 / 下一首 / 播放暂停 / 音量+ / 音量−。
- **滚动行**：上滑（下一个）/ 下滑（上一个）。

每个按钮只有 `down` / `up` 两个事件；点按型动作（粘贴、删除、媒体、滚轮、应用启动、开关翻转）在 `down` 触发即可。

### 5.2 模块划分

| 模块 | 职责 |
| --- | --- |
| 连接配置 | 填电脑 IP、端口；保存最近配置；显示连接状态与重连提示 |
| 按键界面 | 上述分区按钮；按下/松开对应发协议消息；选择 / 切换态有界面提示 |
| 录音模块 | `AudioRecord` 16k / 16bit / 单声道，按 20ms 块读出作为二进制帧发送 |
| WebSocket 客户端 | 连接、断线自动重连、心跳 ping/pong、收发文本/二进制帧 |
| 录音前台服务 | **仅录音期间**起前台服务并显示通知（Android 录音强制要求）；不做常驻强保活 |

### 5.3 所需权限（Android 12+ / 一加 13 ColorOS 17）

`INTERNET`、`ACCESS_WIFI_STATE`、`RECORD_AUDIO`、`FOREGROUND_SERVICE`、`FOREGROUND_SERVICE_MICROPHONE`、`POST_NOTIFICATIONS`；运行时申请录音与通知权限。

### 5.4 保活策略（按需求简化）

- 不纠结后台保活：本软件替代遥控器，使用时 App 在前台。
- 进程被杀后，下次手动启动 App 自动连接最近配置的电脑；WebSocket 层做好自动重连即可。
- 不引导用户设置自启动、电池白名单等（二期如有需要再补）。

## 六、分期计划

### M1：链路打通 + 按键

- 电脑端 WebSocket 服务端 + 动作执行器骨架 + 托盘图标；按键先打印日志，逐步接上真实按键 / 媒体 / 滚轮 / 应用启动 / Alt-Tab / 选区模式。
- 手机端连接配置 + 按键布局 UI + 文本帧收发。
- 验收：手机各按钮能在电脑端触发对应动作；Alt-Tab 会话、选区复制流程进出正常。

### M2：语音推流

- 手机 `AudioRecord` 采集并按协议发 PCM 二进制帧。
- 电脑端环形缓冲 + `sounddevice` 写 CABLE Input；语音按住 / 常开两种方式编排 Ctrl+Win 与麦的启停。
- 验收：按住或点开常开后，微信输入法进入语音输入，从 CABLE Output 拾音，说话上屏；停止后释放快捷键；采样率不变声、无明显卡顿。

### M3：打磨

- 断线重连体验、状态回传、应用栏位可视化配置、UI 精修、音量/增益、延迟观测；必要时引入 Opus 压缩降带宽。

## 七、风险与对策

| 风险 | 对策 |
| --- | --- |
| 音频时序漂移、积压延迟 | 固定块长、环形缓冲、溢出丢旧帧；两端采样率严格对齐 |
| 手机电脑不在同一网段 / AP 隔离 | 同 WiFi 或手机开热点给电脑；M1 先验证可达性 |
| 虚拟声卡未装 / 选不到设备 | 启动检测并在托盘与 `status` 明确提示；不依赖默认录音设备 |
| 修饰键卡住不释放 | 各状态机兜底：断线、异常、取消/确认都强制释放 Alt / Shift / Ctrl / Win |
| 选区模式方向键与导航冲突 | 电脑端按当前模式解释方向键；手机端进入选择/切换态后界面明确提示 |
| 局域网明文 | 自用场景可接受；预留 token，后续可加简单校验 |
| 多一跳延迟 | 局域网通常几十毫秒；实时性不达标再评估压缩或本地识别 |
| 应用启动路径失效 | 配置栏位填绝对路径；启动失败在托盘与 `status` 回传提示 |
