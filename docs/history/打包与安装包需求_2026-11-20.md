## 一、目标与验收口径

一句话目标：**在一台干净的 Windows 10/11 上，用户双击一个 `setup.exe` 到底，重启后用手机就能语音上屏，全程不需要装 Python、不需要装驱动、不需要配防火墙。**

验收清单（缺一不可）：

- [ ] 干净机（无 Python、无 VB-CABLE、无 WebView2 之外的任何前置）安装后，托盘图标正常出现，`8765` 可连。
- [ ] `CABLE Input` / `CABLE Output` 由安装包自动装好，设置页显示「虚拟声卡：已就绪」。
- [ ] 未装驱动时**不能静默降级**：服务需在托盘与设置页明确报「虚拟声卡缺失，语音不可用」，而不是把声音放去物理喇叭。
- [ ] 防火墙 `8765` 入站规则由安装包添加，不需要用户手动点「允许访问」。
- [ ] 卸载后：程序目录、快捷方式、防火墙规则、计划任务、驱动（询问用户是否一并卸载）全部清干净。
- [ ] 覆盖安装（升级）不丢 `config.json` 里的 `remotes[]` token 与四栏位配置。

## 二、交付物组成

```
setup.exe                          ← 安装包外壳（Inno Setup 6，建议）
payload/
  ├─ RemoteMicService/             ← PyInstaller onedir 产物（python 运行时内置）
  │    ├─ RemoteMicService.exe
  │    ├─ _internal/…              ← 依赖（sounddevice 的 PortAudio DLL、pywebview/pythonnet 等）
  │    └─ …
  ├─ vb-cable/                     ← VB-CABLE 驱动包（VBCABLE_Setup_x64.exe + .inf/.sys/.cat）
  ├─ config.example.json
  └─ 使用说明.txt                  ← 含「微信输入法拾音设备选 CABLE Output」这一步
```

要点：

- **主程序用 PyInstaller `onedir`，不要 `onefile`**。onefile 每次启动要解包到临时目录，托盘/驱动/声卡这种常驻型程序会明显拖慢冷启动，且杀软误报率更高。
- 用 `RemoteMicService.exe`（PyInstaller 产出的 GUI 子系统 exe），**不要再沿用 `python.exe run.py` + `start-hidden.vbs`** 的老启动方式；但需保留等价行为：日志写 `%LOCALAPPDATA%\RemoteMic\logs\service.log`，5MB×3 滚动。
- 安装包体积预估：Python 运行时 + numpy/sounddevice/pywebview ≈ 60~90 MB，VB-CABLE 1.1 MB，压缩后 setup ≈ 30~40 MB。

## 三、安装流程（按序执行，每步都要可失败降级）

| 步 | 动作 | 失败处理 |
| --- | --- | --- |
| 1 | 检测系统：Win10/11 x64，`.NET`/VC 运行库（VB-CABLE 与 pythonnet 可能需要） | 不满足则中止并给出明确提示 |
| 2 | **检测 VB-CABLE 是否已装** | 已装则跳过，不重复安装 |
| 3 | **静默安装 VB-CABLE**（64 位） | 失败 → 继续装主程序，但安装结束时弹「语音功能不可用，原因：驱动安装失败」+ 重试入口 |
| 4 | 解包主程序到 `%ProgramFiles%\RemoteMic`（或用户目录，见 §六） | 失败回滚 |
| 5 | 写 `config.json`：仅当不存在时从 `config.example.json` 复制，**已存在绝不覆盖** | — |
| 6 | 加防火墙入站规则 `RemoteMic 8765`（TCP，程序为 RemoteMicService.exe，不按端口全开） | 失败提示，并在设置页显示「防火墙：未放行」 |
| 7 | 创建开始菜单/桌面快捷方式（启动服务、设置） | — |
| 8 | 询问（默认不勾）是否开机自启 → 是则注册计划任务（见 §七） | 拒绝则什么都不做 |
| 9 | 安装后自检：起一次服务 → 读日志确认 `matched audio device: CABLE Input` + `WebSocket listening on 0.0.0.0:8765` → 停掉 | 自检不过则弹窗列具体缺项 |

## 四、VB-CABLE 静默安装（核心需求）

### 4.1 已在本机验证可行的做法

```bat
:: 安装（需管理员）
VBCABLE_Setup_x64.exe -i -h
:: 卸载
VBCABLE_Setup_x64.exe -u -h
```

- `-i` = install，`-h` = 隐藏界面；实测退出码 `0`，**无需重启即可出现设备**（`Get-PnpDevice` 立刻可查）。
- 必须由**已提权的安装进程**调用（Inno Setup 用 `PrivilegesRequired=admin`，在 `[Run]` 段以 `runhidden` 调用即可，不会二次弹 UAC）。
- 若安装进程本身未提权，`Start-Process -Verb RunAs` 会弹 UAC —— 用户点「否」则整段驱动安装失败，按 §三 步 3 降级。

### 4.2 安装前的检测（任一条命中即视为已装）

1. `pnputil /enum-drivers` 输出中含 `vbaudio_cable64` / `vbMmeCable64`；
2. `Get-PnpDevice` 中存在 `FriendlyName -match 'VB-Audio Virtual Cable'` 且 `Status=OK`；
3. 音频端点注册表 `HKLM\SYSTEM\CurrentControlSet\Enum\SWD\MMDEVAPI` 下含 CABLE 端点（前两条已足够）。

**注意**：检测必须以「驱动节点存在」为准，不能以「名字里带 CABLE」为准 —— 某些主板/声卡驱动会自带 CABLE 字样设备。

### 4.3 安装后的程序侧自检（服务启动时必须做）

- `sounddevice.query_devices()` 里找 `max_output_channels>0` 且名字含 `CABLE Input`，并对命中的候选**逐个试开 16 kHz 流**（WASAPI 在没有把 CABLE 改成 16 kHz 时开不了，会报 `-9997`，必须能自动落到 DirectSound）→ 成功则 `status.audio_ready=true`。
- 未命中或全部试开失败：**绝不回落到默认输出设备**（原代码的回落行为已于 2026-11-20 移除）。此时应：语音帧直接丢弃、托盘图标变灰黄、`status` 帧回 `audio_ready=false`、手机端提示「电脑虚拟声卡未就绪」。程序侧已有 `AudioOut.ready` 与 `AudioOut.matched_device` 可直接取值。
- 理由：回落默认会让「手机说话时电脑喇叭放出来」，在办公室/会议室是尴尬且危险的错误形态，比直接不可用更糟。

### 4.4 授权与分发注意（需确认，不要默认可商用）

- VB-CABLE 是 VB-Audio 的 donationware，官方允许**原样免费分发**；但**打包进商业产品/对外发布的安装包**是否需另行授权，需在正式发布前确认 VB-Audio 的条款或邮件询问。
- 自用/团队内部使用，按现行做法直接内置即可。
- 驱动为 VB-Audio 自签（非 WHQL）。本机 Win11 实测只弹 UAC、无「无法验证发布者」警告；但在开启 **Secure Boot + 驱动黑名单策略** 或企业组策略的机器上可能被拦。安装包的失败提示要能指向这个原因。

## 五、WebView2 与设置页

- 设置页走 `pywebview`（`settings_web.py`），依赖系统 WebView2 Runtime。Win11 一般自带；Win10 可能没有。
- 安装包需检测：`HKLM\SOFTWARE\WOW6432Node\Microsoft\EdgeUpdate\Clients\{F1E7E2A4-...}` 或 `C:\Program Files (x86)\Microsoft\EdgeWebView\Application\*` 存在即为有。
- **缺失时的策略**：不静默崩，走现有 tkinter 回退（`settings_ui.py`），同时在安装包里附 WebView2 Evergreen Bootstrapper（约 1.5 MB，联网安装）作为可选步骤。
- 不要用 `pywebview` 打包内置 CEF —— 体积会翻到 100 MB 以上，收益不匹配。

## 六、安装位置、权限与账号模型（与现有「服务由谁派生」原则一致）

- **服务绝不能被安装包或任何宿主应用的进程树派生**（例如不能由豆包/编辑器起子进程），否则宿主退出会连带停服。
- 推荐两种常驻形态，按用户选择：

| 形态 | 做法 | 优缺点 |
| --- | --- | --- |
| A. **交互式托盘**（默认） | 用户登录后自启托盘进程（`RemoteMicService.exe`），托盘常驻 | 与现有代码完全兼容（pynput 键盘注入、`SetForegroundWindow` 都要求交互式会话），推荐保持 |
| B. 计划任务（SYSTEM） | 计划任务以 SYSTEM 在开机时启动 | 能无人值守，但**在会话 0 里无法做鼠标键盘注入与窗口置前**，会废掉 M1 的一半功能 → **不建议用于主服务** |

结论：**主服务保持「用户会话内托盘进程」**；若以后要做「开机即监听」，只能做「登录时触发」的计划任务（`/SC ONLOGON`），不要做 SYSTEM 会话 0。

- 安装目录：`%ProgramFiles%\RemoteMic` 需要写权限的只有安装/升级本身；运行期的 `config.json`、`logs`、`icons` 缓存统一放 `%LOCALAPPDATA%\RemoteMic\`（避免 UAC 虚拟化与多用户互相覆盖）。
  与现状的偏差：`store.CONFIG_PATH` 现在指向 `pc-service/config.json`（仓库内），打包后要改成 `%LOCALAPPDATA%\RemoteMic\config.json`，并做一次「旧路径存在则迁移」的兼容处理。

## 七、防火墙与开机自启

- 防火墙：`netsh advfirewall firewall add rule name="RemoteMic 8765" dir=in action=allow protocol=TCP localport=8765 program="%ProgramFiles%\RemoteMic\RemoteMicService.exe" profile=private,domain` —— 只放行**专用/域网络**，不要放行公用网络（咖啡馆/机场 Wi-Fi 场景）。
- **不要再踩 `pythonw.exe` 的坑**：本机 `pythonw.exe` 存在入站 Block 规则，历史上导致手机连不上（见 `开发与验收清单.md` §P4.5）。打包后主程序是自己的 exe，规则按 exe 精确放行即可，但仍需在首次连接失败时给出「检查防火墙」的排查提示。
- 开机自启：注册 `HKCU\...\Run` 或计划任务 `/SC ONLOGON /RL LIMITED`，托盘「设置」里提供勾选项，**默认不勾**（沿用文档既有约定）。
- 卸载时同步删除：防火墙规则、自启项/计划任务、快捷方式；`%LOCALAPPDATA%\RemoteMic` 下的 `config.json` **询问后再删**（含 token，删了要重新扫码绑定）。

- 升级：原地覆盖 `%ProgramFiles%\RemoteMic`，保留 `%LOCALAPPDATA%\RemoteMic\config.json`；版本号写入注册表 `Uninstall\RemoteMic`（Inno 自带）。
- 卸载顺序：先停服务（任务栏托盘退出 / `taskkill`）→ 删防火墙规则 → 删自启 →（询问）卸载 VB-CABLE → 删程序目录 →（询问）删用户配置。

### 11.3 已知注意事项

1. **Inno 的 `UsedUserAreasWarning`**：`PrivilegesRequired=admin` 下写 HKCU 会落到「提权后的那个用户」。同机同用户提权时是同一个 Hive，正常；若用「另一个管理员账号」跑安装，自启会写进那个账号。托管环境如需严格，可把自启改成安装完后由用户首次启动托盘时勾选（托盘勾选项就是默认路径）。
2. **`contents_directory=_internal`**：`vb-cable` 落在 `{app}\_internal\vb-cable\`，`.iss` 里按这个路径调安装器；改 spec 的布局要同步改 iss。
3. **驱动为 VB-Audio 自签（非 WHQL）**：Secure Boot + 驱动黑名单策略或企业组策略会拦；安装完成后 `CurStepChanged` 会检测一次，没装上就弹提示指向设置页的「安装虚拟声卡」。
4. **安装包未做代码签名**：Windows SmartScreen 首次运行会提示「未知发布者」，正式分发前需买证书签名。
5. **`build_installer.ps1` 必须带 UTF-8 BOM**：Windows PowerShell 5.1 会把无 BOM 的 UTF-8 当 ANSI 读，脚本里的中文注释/提示会变乱码并直接报「字符串缺少终止符」。已按 BOM 保存；用 `pwsh` 或 `powershell` 跑都正常。
