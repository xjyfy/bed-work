> 第四轮真机实测后修复：⑭ **窗口未真正前置是多条问题的共同根因**——后台 Python 进程被 Windows 前台锁拒绝 `SetForegroundWindow`，目标窗口只闪任务栏、仍停留在原前台窗口，注入的鼠标/键盘/滚轮消息发给了前台其他窗口（表现为：豆包栏位聚焦无效、Chrome 窗口被还原缩小、抖音滚轮/方向键/空格都无反应）。已改用 `AttachThreadInput(前台线程ID, 当前线程ID, True)` 附加输入队列后再 `ShowWindow`+`BringWindowToTop`+`SetForegroundWindow`，解除附加，本机实测成功把抖音从前台豆包处抢到前台。⑮ 豆包挂两个窗口，EnumWindows 先命中离屏(位置 -9999)无标题辅助窗；已过滤离屏/无标题辅助窗，按(有标题, 在屏, 未最小化)排序取主窗；前置时按原 `showCmd` 决定最大化 / 还原，不再无条件把全屏窗口缩小。⑯ 滚轮注入前先把鼠标移到前台窗口客户区中心，确保滚轮命中目标窗口。⑰ 退出选区时轻触方向键取消文字选中高亮。

> 第四轮本机直接验证（非推测）：Attach 前置成功后，鼠标居中连发滚轮，抖音画面/章节发生切换，**滚轮在抖音已被接收**；空格注入后视频仍在播放、未暂停，单击画面中心同样未暂停，疑焦点停在底部弹幕输入框吃掉空格，属抖音 Electron webview 的合成消息适配边界，待真实遥控场景复测。
>
> **勘误（第五轮复核）**：上一条"滚轮在抖音已被接收"系误判——画面变化是同一视频内合集章节/进度条自然走动，视频并未切换；人工键鼠复测抖音滚轮/方向/空格均可控制。诊断派生进程中 `SetCursorPos`/`SetPhysicalCursorPos`/`SendInput` 绝对移动均被静默拒绝（光标恒停原位），鼠标落点无法在该受限上下文验证，需真机独立 bat 进程复测。

> 第五轮真机反馈后修复（参照本地 SayAll 基线仓库注入方案）：⑱ **进程最早期声明 Per-Monitor V2 DPI 感知**（`run.py` 最先调用 `SetProcessDpiAwarenessContext(-4)`，失败回退 `shcore.SetProcessDpiAwareness(2)`），避免高缩放（本机 150%，物理 2560×1440 / 逻辑 1707×960）下窗口矩形与光标坐标被虚拟化、落点偏移。⑲ **滚轮改为低层 `SendInput` 逐格发送**：每格 `mouseData=±120`（WHEEL_DELTA），格间 20ms 贴近物理滚轮节奏；发送前先把光标移到前台窗口客户区中心，光标移动按 `SetPhysicalCursorPos → SetCursorPos → SendInput 绝对坐标` 三 API 回退；不再用 pynput 聚合滚轮。⑳ 选区复制成功（Ctrl+C）后立即轻触方向键取消选中高亮，退出选区分支保留方向键兜底。**键盘注入本轮未切换扫描码路径**：真机普通应用方向键/确认/退格/音量/媒体键全部正常，证明 vk 注入有效；抖音方向/空格异常优先排查弹幕输入框焦点，待真机确认确为扫描码兼容问题后再按 SayAll 表移植 `wVk=0 + KEYEVENTF_SCANCODE`（扩展键带 EXTENDEDKEY）。

> 第六轮真机反馈后修复：㉑ **切到抖音后无法切回浏览器/豆包**。本机复现定位：前台为抖音时 `AttachThreadInput` 返回 `ERROR_ACCESS_DENIED(5)` 被拒，附加输入队列失败后 `SetForegroundWindow` 被前台锁挡住，目标窗口读回仍是抖音。前置流程重写为：`LockSetForegroundWindow` 解锁 → `AttachThreadInput`（失败不阻断）→ ShowWindow/BringToTop/SetForegroundWindow → **前台读回复核 3×100ms**（成功判据是 `GetForegroundWindow` 读回属于目标，不是 SetForegroundWindow 的 BOOL）→ 仍失败则**最小化当前前台窗口，再还原并置前目标**作为最后兜底。
>
> **事故与回退（第六轮当晚）**：初版前置兜底曾移植 SayAll 的"Alt 物理解锁"（SendInput 按下 Alt→置前→松开 Alt）。该路径在注入边沿未补齐时会把 **Alt 卡在按下态**，表现为全局键盘无法输入、双击文件弹属性窗口。已紧急释放卡住的 Alt，并**彻底移除 Alt 注入路径**（删除 `_alt_edge`/键盘结构/`_VK_MENU` 等），前置只保留 attach + 读回复核 + 最小化兜底；代码路径不再发送任何 Alt/Ctrl/Shift 边沿注入（Alt-Tab 会话仍走 pynput press/release，断线由 `reset_modifiers` 兜底释放）。诊断派生进程对抖音线程附加被拒属受限上下文表现，真机独立 bat 进程的附加行为与最小化兜底效果仍需复测。

## 二、电脑端运行

### 2.1 运行环境（独立 Python，已装好并自检通过）



* 解释器：独立安装的 **Python 3.13.17**，路径 `%LOCALAPPDATA%\Programs\Python\Python313\python.exe`（不依赖豆包运行时目录）。

* 已装依赖：`websockets 17.4 / sounddevice 0.5.6 / pynput 1.8.2 / numpy 2.5.4 / pystray 0.19.5 / Pillow 13.0.0`。

* 换机 / 重装依赖：用该解释器执行 `"%LOCALAPPDATA%\Programs\Python\Python313\python.exe" -m pip install -r requirements.txt`。

### 2.2 启动（手动，不开机自启）

**方式一（推荐）**：双击 `pc-service\启动电脑端服务.bat`。

**方式二（命令行）**：



```
cd pc-service
"%LOCALAPPDATA%\Programs\Python\Python313\python.exe" run.py
```



* 监听 `0.0.0.0:8765`；右下角托盘图标显示连接状态；关闭弹出的控制台窗口即停止服务。

* **不开机自启**：每次重启电脑后需手动启动一次，手机才能连上。

* 服务为独立进程，不由豆包派生。

### 2.3 配置（config.json）



* `port`：WebSocket 端口。

* `sample_rate / channels / sample_width_bytes / frame_ms`：音频格式，与手机端对齐，勿改。

* `audio_device_keyword`：虚拟声卡名称关键字，默认 `CABLE Input`。

* `voice_hotkey`：语音快捷键，**已写死&#x20;**`["ctrl","win"]`，勿改。

* `apps`：1\~4 栏位填 Windows 应用**绝对路径**，留空则该栏位启动时仅记日志。路径里的反斜杠必须写成正斜杠 `/` 或双反斜杠 `\\`（单反斜杠是非法 JSON 转义，会导致启动报 `Invalid escape`），例如：`"C:/Program Files/App/app.exe"`。
