# 电脑端 v1.1.1 · 修「抖音最大化 + 悬停任务栏」时截屏无响应 / 偶现未连接

发布日期：2026-11-21

## 下载

- **电脑端**：`RemoteMicSetup-1.1.1.exe`（Windows 10/11 x64，约 28 MB）
- 手机端无改动，沿用 `RemoteMic-1.2.1.apk`。

## 问题

抖音窗口最大化、鼠标悬停在 Windows 任务栏时，手机点「截屏」极大概率没反应，偶现提示「未连接电脑」。

## 根因（两个缺陷叠加）

1. **托盘 GDI 阻塞事件循环**：连接状态广播会在 asyncio 循环里同步刷托盘图标/菜单（`Shell_NotifyIcon`、重建 HMENU）。这些是同步调用 explorer 的 GDI 操作；任务栏忙（悬停缩略图预览 + 最大化硬件视频）时会 stall 数秒 → 循环卡住 → WebSocket pong 超时 → 手机重连 → 又广播又刷托盘 → 再 stall，**自激成重连风暴**。
2. **截屏回包发错连接**：抓图期间若该遥控器发生重连，回包仍发给请求时的旧 socket（已被顶替），手机收不到 → 「截屏没反应」。

## 修复

- 托盘图标/tooltip/菜单刷新移到专用 `tray-gdi` worker 线程，状态变更只记标记、合并执行；asyncio 循环不再做任何托盘 GDI。
- 截屏回包改发给该遥控器的**当前**连接（`_current_client`），重连后不再丢图。
- 状态广播对单客户端 send 加 2s 超时，防止死 socket 发送缓冲满拖住循环。

## 验证（一加 13 / ColorOS 17 + Win11 真机）

- 复现条件：抖音最大化 + 光标置于任务栏。修复前该条件下截屏丢包、`ws failure: ping/pong 10s` 超时、重连计数持续上涨、出现 `send failed (screenshot): ... replaced`。
- 修复后同条件连做「截屏 → 关闭 → 再截屏」4 轮：截屏全部送达、**0 次重连、0 次 ping 超时、0 次 send failed**，连接数恒为 1。
- 抓屏本身耗时实测 ~65-105ms（各条件下均正常），排除 ImageGrab stall。

覆盖安装即可，`config.json` 与绑定不受影响。
