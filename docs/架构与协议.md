线程模型（关键，改代码前必看）：

| 线程 | 承担的活 |
| --- | --- |
| 主线程 | pywebview 的设置窗口（**pywebview 只能主线程**）；无窗口时轮询 `settings_queue` |
| asyncio 线程 | WebSocket 服务、协议帧解析与分发、状态广播 |
| 线程池（`asyncio.to_thread`） | 键鼠注入 / 窗口置前 / 写剪贴板 / 截屏 / 文件分块读写与 rename。**这些全是阻塞调用，一律不许留在 asyncio 线程里**；`_handler` 逐帧 `await`，所以同一连接的按键与文件块顺序不变 |
| pystray 线程 | 托盘菜单与回调；「发送文件到手机…」会再开 `tray-send-files` 线程 |
| `tray-gdi` 线程 | 托盘图标/tooltip/菜单的 GDI 刷新（`Shell_NotifyIcon`、重建 HMENU）。**这些是同步调用 explorer 的操作，任务栏忙时可能 stall 数秒，绝不在 asyncio 循环里做**；状态变更只记 dirty 标记，由该线程合并执行 |
| `slot-icons` 线程 | 启动时预热应用图标 |
| 手机端发送线程 | `file-send` daemon 线程逐文件发块（**手机端快照回调必须切主线程**，否则 Toast 直接崩） |

## 三、协议

单向 JSON 文本帧 + 二进制帧（文件块），首帧必须认证。

### 3.1 认证与状态

| 方向 | 帧 | 说明 |
| --- | --- | --- |
| 手机→电脑 | `{"type":"auth","token","device"}` | 首帧认证 |
| 电脑→手机 | `auth_ok {active, computer, status, perms{files,screenshot}, files_allowed}` | 认证成功（`perms` 决定「传文件」「截图」是否可用；`files_allowed` 为旧版手机端的兼容字段） |
| 电脑→手机 | `perms {files, screenshot, files_allowed}` | 设置页改了权限后**实时推给所有在线连接**（不论是否持有控制权）；`reload_config` 里先比对缓存值，变了才推 |
| 电脑→手机 | `auth_fail {reason}` | token 无效 |
| 双方 | `ping {ts}` / `pong {ts}` | 保活，10 s 超时判死 |
| 手机→电脑 | `hello {}` | 客户端自我介绍（连接后立即发） |
| 电脑→手机 | `status {computer, active_id, clients[{id,name,ip,active,reconnects,uptime_s}], voice, active, audio_ready, mode, tab_index, audio{ready,device,hostapi,level_ms,overflows,underruns,dropped_samples,frames_in,frames_out}}` | 状态广播；`audio_ready` 表示输出流是否已打开（VB-CABLE 未装或打不开为 false），`mode` 为 `normal` / `switcher`（停在 Alt+Tab 浮层），`tab_index` 是 Ctrl+1..9 循环的当前位置（0 = 未切过）。`audio` 是 v1.0.2 新增的音频可观测（`level_ms` 环形缓冲水位毫秒，`overflows`/`underruns` 溢出与欠载次数，`dropped_samples` 溢出丢弃样本，`frames_in/out` 收放帧数）；`clients[].reconnects` 是同一遥控器累计重连次数，`uptime_s` 为当前会话时长（v1.0.2，配合日志 `remote reconnect #n` 判断被杀后是否自动重连） |
| 手机→电脑 | `switch_active {id}` | 手动切换控制权 |

> `status` 的广播时机：建连、断连、切换控制权，**以及 `mode` / `tab_index` 真的发生变化时**（`_on_control` 在分发前后比较这两个值，变了才补一帧，避免每个方向键都刷全量 status）。早期只在前三者广播，导致手机端永远收不到浮层/Tab 状态变化。

### 连接数量与「踢旧保新」（v1.2.3 起）

- 电脑端对同一台遥控器（同一 `remote_id`）**只保留最新一条连接**：新连接认证时把旧连接按 **close code `4001` / reason `replaced`** 关闭，并 `abort` 底层传输，确保旧 socket 不残留成半死的 ESTABLISHED。
- 手机端收到 `4001` 视为「被别的连接接管」，**退让 10 秒再重连**，不再立即重试（否则两条连接会互相踢，形成每 20 秒一次的重连风暴）。
- **客户端同一时刻只维持 1 条连接**：建连单飞 + 代际号，非强制重连时已有 socket 直接跳过；旧 socket 用 `cancel()` 立即断。多条并存会互相顶掉，且截图/文件回包会发到刚被顶掉的那条上（表现为"按键能用但截屏/传文件没反应"）。
- `_send_json` 对 `screenshot` / `file_ack` / `file_reject` / `file_result` / `file_offer` 这类「请求-回包」消息，发送失败时**补发一次到当前最新连接**。

### 控制权闸门与设备权限（v1.2.5 起）

`_on_control()` 开头的 active 检查只对**控制类**消息生效（`key` / `send` / `voice` / `voice_toggle` / `launch` / `switcher` / `clip` / `mic`）。下面这些在待命状态同样放行（`STANDBY_ALLOWED_TYPES`）：`screenshot`、`file_begin` / `file_end` / `file_abort` / `file_accept`、`switch_active`——它们不抢键盘焦点、不出声，只受该设备自己的权限约束。

每台绑定设备有三档权限（`config.json` 里 remote 的三个字段）：

| 字段 | 含义 |
| --- | --- |
| `perm_all` | 总闸；为真时两个子权限都放开，设置页里另两项置灰 |
| `perm_files` | 允许这台设备往电脑传文件 |
| `perm_shot` | 允许这台设备抓取电脑屏幕 |

- `store.remote_perms(remote)` 返回有效 `(files, shot)`；`store.set_remote_perms(config, id, all_on, files, shot)` 统一落盘，并把 `receive_files` 回写成 `perm_files or perm_shot` 兼容旧版电脑端。
- 老配置（只有 `receive_files`）在 `ensure_basics()` 里迁移：两个子权限都取 `receive_files` 的值，升级后行为不变。
- 权限变更后 `reload_config()` 会对 `_clients_snapshot()` 全量比对并推 `perms` 帧，天然覆盖「待命中的连接」。

### 3.2 控制

| 帧 | 参数 | 落地 |
| --- | --- | --- |
| `key` | `code`（见下表）；`action` 目前被忽略，所有 code 都按「点一下」处理 | pynput 键盘注入 / 滚轮 |
| `send` | 无 | 三级优先：`slot_send_hotkey` → 按前台程序查 `send_hotkey` → `default`（Enter）。前台是商店应用（`ApplicationFrameHost.exe`）时先遍历子窗口解析到真实进程再查表 |
| `launch` | `slot`（"1".."4"） | 已在运行→切窗口（含屏幕外搬回），否则启动。**只认 slot，不认 exe 路径** |
| `switcher` | `action`（enter/next/prev/confirm/cancel） | Alt-Tab 会话 |
| `voice` | `action`（down/up） | push-to-talk 开始/结束 |
| `voice_toggle` | `action`（on/off/toggle） | 常开开关 |
| `mic` | `action`（start = 开，其它 = 关） | 直接切 `AudioOut.set_active` |
| `clip` | `text` | 写剪贴板 + `clip_policy` 决定是否补 Ctrl+V；上限 100000 字符 |
| `screenshot` | 无 | 抓全屏→长边 1600→JPEG→base64 回 `screenshot {ok,w,h,bytes,image}`；无截图权限时回 `{ok:false, reason:"perm_denied"}`。**待命状态也可发** |
| `switch_active` | `id` | 切换控制权。**待命状态也可发**（否则待命方没法主动申请接管） |

`key.code` 全集（`actioner._KEY_MAP` + 特例分支）：

| code | 注入 | code | 注入 |
| --- | --- | --- | --- |
| `up` / `down` / `left` / `right` | 方向键 | `prev_track` / `next_track` | 媒体 上一首 / 下一首 |
| `ok` | Enter（浮层中=确认切换） | `play_pause` | 媒体 播放暂停 |
| `esc` | Esc（浮层中=退出并释放 Alt） | `video_play_pause` | 空格（网页视频只认空格） |
| `delete` | Backspace | `vol_up` / `vol_down` | 媒体 音量 ± |
| `new_chat` | Ctrl+N | `scroll_next` / `scroll_prev` | 滚轮下 / 上（逐格 `SendInput`） |
| `tab_next` | Ctrl+1..9 循环 | `send` | 等同 `send` 帧 |

> **没有独立的 `media` / `wheel` 帧**：媒体键与滚轮都走 `key` 的 code。早期协议表列过这两个帧，服务端从未实现，已删。

### 3.3 快捷应用

手机认证成功后，电脑端主动推一帧（设置页保存后也会重推）：

```json
{"type":"apps","slots":[{"slot":"1","name":"微信","icon":"data:image/png;base64,..."}]}
```

手机把名称/图标写进本地 prefs，冷启动没连上也能先显示上次的。

### 3.4 文件互传

文本帧：

| 帧 | 方向 | 字段 |
| --- | --- | --- |
| `file_begin` | 手机→电脑 | `transfer_id,name,size,mime,index,count` |
| `file_ack` | 电脑→手机 | `transfer_id,name`（name 是清洗后的最终名） |
| `file_reject` | 电脑→手机 | `transfer_id,reason`（开关关 / 超 2 GB / 超 50 个 / 无法创建文件） |
| `file_end` | 双向 | `transfer_id,ok,reason` |
| `file_result` | 电脑→手机 | `transfer_id,ok,name,dir,count` |
| `file_abort` | 手机→电脑 | `transfer_id,reason` |
| `file_offer` | 电脑→手机 | `transfer_id,name,size,mime,index,count` |
| `file_accept` | 手机→电脑 | `transfer_id` |
| `files_allowed` | 电脑→手机 | `allow`（设置页开关变化即时同步） |

二进制帧：`b"FCHN"`（4 字节 MAGIC）+ 数据，**256 KB 一块**；靠 MAGIC 前缀与语音 PCM 帧区分。

时序（手机→电脑）：`file_begin` → 电脑校验（开关/大小/数量/能否创建文件）→ **`file_ack` 或 `file_reject`** → 手机**等到 ack 才开始**逐块二进制 → `file_end` → 电脑 `finish()`（校验大小后把 `.part_<tid>_<name>` 原子改名成正式名）→ `file_result`。

> 手机端等 ack 的上限 10 s，超时发 `file_abort` 收尾；收到 reject 立刻停发并提示，不会把整个文件白推一遍。
> 发送侧还有背压：OkHttp 待发送队列超过 2 MB 就等回落，持续 30 s 不回落判停滞并中止（否则弱网/慢盘时 256 KB 块会在内存里堆到 OOM）。

时序（电脑→手机）：`file_offer` → 等 `file_accept`（20 s 超时则跳过该文件）→ 逐块二进制（`tx_lock` 串行）→ `file_end`。手机中途取消会回 `file_end{ok:false}`，电脑据此停发。

约束：单文件 ≤ 2 GB、一次 ≤ 50 个、不做断点续传、失败/取消删 `.part`、启动时清理 24 h 前 `.part` 残留。
收到的字节数**不许超过 `file_begin` 声明的 size**，超了立刻中止（防止谎报小尺寸写满磁盘）。

## 四、音频链路细节

1. 手机采集 16 kHz/16 bit/mono PCM，20 ms/帧（320 samples）。
2. 电脑端 `AudioOut` 按关键字筛候选输出设备，**WASAPI → DirectSound → 其它逐个试开**；WASAPI 不开重采样，16 kHz 在 VB-CABLE 默认 48 kHz 时会报 `-9997`，因此不能只取首个。
3. 回调里从环形缓冲取 PCM 写入；断流时补静音，避免爆音。
4. 未就绪 → `feed()` 直接丢帧，**绝不回落物理扬声器**；`status.audio_ready=false`，手机端据此把语音键置半透明、副标题显示「电脑声卡未就绪」，按下只提示不起录音服务；正在进行的语音会话会被收掉。
5. `AudioOut` 有两把锁：`_lock` 只保护环形缓冲与计数，`_life` 串行化开/关流。**绝不能持 `_lock` 跨越 PortAudio 调用**——回调要抢 `_lock`，而 `feed()` 跑在 asyncio 线程里，持锁开关流会阻塞整个事件循环（实测旧实现 `stop()` 持锁 263 ms）。
6. 奇数长度的 PCM 帧截到偶数字节再转 int16，不让 `frombuffer` 抛异常断掉整条连接。

> 托盘图标颜色只反映**遥控器连接状态**（灰=未连接 / 绿=控制中 / 黄=已连接但无控制权），**不反映声卡就绪**；声卡状态看 `status.audio_ready` 与设置页的「音频输出」卡片。`status.voice` 是「用户是否按下了说话」，也不是就绪标志。

## 五、安全模型

- 局域网自用：监听 `0.0.0.0:8765`，token 认证（每台遥控器独立 token，存 `config.json`）。
- 卸载/删除遥控器即失效；token 泄露的处理方式是删除该遥控器并重新扫码。
- 文件落盘对**文件名和 `transfer_id` 都做**目录穿越清洗（`../`、分隔符、绝对路径）与保留名规避（按首个点前的整段判断，`nul.a.b` 也拦）；`transfer_id` 不合格时服务端自生成。接收目录可由用户改动。
- 同名文件用「`os.rename` 失败就试下一个候选名」的方式落盘，**不覆盖已有文件**（先 `exists()` 再 `replace()` 有竞态，且 Windows 的 `replace` 本身会覆盖）。
- 电脑→手机方向的 `file_offer.name` 同样清洗后才落盘。
- 防火墙规则只放行专用/域网络的 8765，不放行公用网络。
- 截屏与文件内容只在链路中走，不写第三方位置（截屏全程内存）；手机端日志不打印帧内容（截屏 base64、二维码 token 都不进 logcat）。
- 手机端 `allowBackup=false`：绑定 token 明文存 SharedPreferences，不允许随系统备份外流。
