## 一、组件与数据流

```
┌─────────────── 手机（Android, Kotlin） ───────────────┐
│ MainActivity（五分区界面）                              │
│  ├ RemoteWsClient（OkHttp WebSocket）                  │
│  ├ FileTransferManager（选文件后的分块发送/接收）       │
│  ├ TransferBus（进程内进度总线）                        │
│  └ TransferService（传输期短时前台服务，通知栏进度）    │
└───────────────────────┬───────────────────────────────┘
                        │ ws://<PC-IP>:8765（同一局域网）
┌───────────────────────┴──── 电脑（Python） ────────────┐
│ run.py（入口：DPI 声明 / --install-driver 分流）        │
│ server.RemoteMicService                               │
│  ├ websockets 服务端（0.0.0.0:8765，token 认证）       │
│  ├ actioner.Actioner（pynput 键鼠注入、窗口置前）      │
│  ├ audio_out.AudioOut（PCM → CABLE Input）            │
│  ├ files.*（接收落盘、.part、清洗、下载目录解析）      │
│  ├ applist.*（应用列表、256px 图标导出与缓存）         │
│  ├ store.*（config.json 原子读写、绑定、二维码）       │
│  ├ tray.Tray（pystray 托盘，独立线程）                 │
│  ├ settings_web（pywebview 设置页，主线程）            │
│  └ driver / autostart / filedialog / paths（系统集成） │
└───────────────────────────────────────────────────────┘
```

线程模型（关键，改代码前必看）：

| 线程 | 承担的活 |
| --- | --- |
| 主线程 | pywebview 的设置窗口（**pywebview 只能主线程**）；无窗口时轮询 `settings_queue` |
| asyncio 线程 | WebSocket 服务、所有协议帧、文件分块读写（`asyncio.to_thread`） |
| pystray 线程 | 托盘菜单与回调；「发送文件到手机…」会再开 `tray-send-files` 线程 |
| `slot-icons` 线程 | 启动时预热应用图标 |
| 手机端发送线程 | `file-send` daemon 线程逐文件发块（**手机端快照回调必须切主线程**，否则 Toast 直接崩） |

## 二、路径与数据

| 内容 | 路径 |
| --- | --- |
| 程序（打包后） | `%ProgramFiles%\RemoteMic\RemoteMicService.exe` + `_internal\` |
| 运行期数据 | `%LOCALAPPDATA%\RemoteMic\`（`config.json` / `logs\service.log` / 图标缓存） |
| 图标缓存 | `%LOCALAPPDATA%\remote-mic\icons\<md5(exe)[:16]>_256.png` |
| 手机传来文件 | 默认系统「下载」目录（`SHGetKnownFolderPath(FOLDERID_Downloads)`），可在设置页改 |
| 手机接收文件 | `Download/RemoteMic/`（MediaStore，`IS_PENDING`） |
| 随包资源 | `_internal\vb-cable\`（驱动）、`config.example.json` |

`remote_mic/paths.py` 是唯一解析入口：`is_frozen()` / `app_dir()` / `data_dir()` / `config_path()` / `log_dir()` / `vendor_dir()`。
开发期首次运行会把仓库 `pc-service/config.json` 复制到 `%LOCALAPPDATA%`（旧文件不删）。

## 三、协议

单向 JSON 文本帧 + 二进制帧（文件块），首帧必须认证。

### 3.1 认证与状态

| 方向 | 帧 | 说明 |
| --- | --- | --- |
| 手机→电脑 | `{"type":"auth","token","device"}` | 首帧认证 |
| 电脑→手机 | `auth_ok {active, computer, status, files_allowed}` | 认证成功（`files_allowed` 决定「传文件」是否可用） |
| 电脑→手机 | `auth_fail {reason}` | token 无效 |
| 双方 | `ping {ts}` / `pong {ts}` | 保活，10 s 超时判死 |
| 手机→电脑 | `hello {}` | 客户端自我介绍（连接后立即发） |
| 电脑→手机 | `status {computer, active_id, clients[], voice, active}` | 状态广播 |
| 手机→电脑 | `switch_active {id}` | 手动切换控制权 |

### 3.2 控制

| 帧 | 参数 | 落地 |
| --- | --- | --- |
| `key` | `key`（up/down/left/right/enter/backspace/tab/...） | pynput 键盘注入 |
| `media` | `action`（play_pause/next/prev/vol_up/vol_down/space） | 媒体键 |
| `wheel` | `delta` | 滚轮 |
| `send` | `slot`（可选） | 按 `slot_send_hotkey` 或前台程序查表发 Enter / Ctrl+Enter |
| `launch` | `slot` / `exe` | 已在运行→切窗口（含屏幕外搬回），否则启动 |
| `switcher` | — | Alt-Tab 会话 |
| `voice` | `on` | 开启/关闭语音会话 |
| `voice_toggle` | — | 语音键组合 |
| `mic` | — | 麦克风相关开关 |
| `clip` | `text` | 写剪贴板 + `clip_policy` 决定是否补 Ctrl+V |
| `screenshot` | — | 抓全屏→1600→JPEG→base64 回 `screenshot {ok,w,h,bytes,image}` |

### 3.3 快捷应用

手机认证成功后，电脑端主动推一帧（设置页保存后也会重推）：

```json
{"type":"apps","slots":[{"slot":"1","name":"微信","icon":"data:image/png;base64,..."}]}
```

手机把名称/图标写进本地 prefs，冷启动没连上也能先显示上次的。

### 3.4 文件互传

文本帧：

| 帧 | 方向 | 字段 |
| --- | --- | --- |
| `file_begin` | 手机→电脑 | `transfer_id,name,size,mime,index,count` |
| `file_ack` | 电脑→手机 | `transfer_id` |
| `file_reject` | 电脑→手机 | `reason`（开关关 / 超 2 GB / 超 50 个） |
| `file_end` | 双向 | `transfer_id,ok,reason` |
| `file_result` | 电脑→手机 | `ok,name,dir,count` |
| `file_abort` | 手机→电脑 | `reason` |
| `file_offer` | 电脑→手机 | `transfer_id,name,size,mime,index,count` |
| `file_accept` | 手机→电脑 | `transfer_id` |
| `files_allowed` | 电脑→手机 | `allow`（设置页开关变化即时同步） |

二进制帧：`b"FCHN"`（4 字节 MAGIC）+ 数据，**256 KB 一块**；靠 MAGIC 前缀与语音 PCM 帧区分。

时序（手机→电脑）：`file_begin` → 电脑校验（开关/大小/数量）→ 逐块二进制 → `file_end` → 电脑 `finish()`（校验大小后把 `.part_<tid>_<name>` rename 成正式名）→ `file_result`。

时序（电脑→手机）：`file_offer` → 等 `file_accept`（20 s 超时则跳过该文件）→ 逐块二进制（`tx_lock` 串行）→ `file_end`。

约束：单文件 ≤ 2 GB、一次 ≤ 50 个、不做断点续传、失败/取消删 `.part`、启动时清理 24 h 前 `.part` 残留。

## 四、音频链路细节

1. 手机采集 16 kHz/16 bit/mono PCM，20 ms/帧（320 samples）。
2. 电脑端 `AudioOut` 按关键字筛候选输出设备，**WASAPI → DirectSound → 其它逐个试开**；WASAPI 不开重采样，16 kHz 在 VB-CABLE 默认 48 kHz 时会报 `-9997`，因此不能只取首个。
3. 回调里从环形缓冲取 PCM 写入；断流时补静音，避免爆音。
4. 未就绪 → 语音整体禁用 + 托盘变黄 + `status.voice=false`，**绝不回落物理扬声器**。

## 五、安全模型

- 局域网自用：监听 `0.0.0.0:8765`，token 认证（每台遥控器独立 token，存 `config.json`）。
- 卸载/删除遥控器即失效；token 泄露的处理方式是删除该遥控器并重新扫码。
- 文件落盘做目录穿越清洗（`../`）与保留名规避；接收目录可由用户改动。
- 防火墙规则只放行专用/域网络的 8765，不放行公用网络。
- 截屏与文件内容只在链路中走，不写第三方位置（截屏全程内存）。
