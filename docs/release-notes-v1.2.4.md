# v1.2.4 · 修「多次点开应用 / 连续截屏就断线重连」

发布日期：2026-11-21

## 下载

- **手机端**：`RemoteMic-1.2.4.apk`（Android 8.0+，约 6 MB，`versionCode=7`）
- **电脑端**：`RemoteMicSetup-1.1.2.exe`（Windows 10/11 x64，约 28 MB；本版电脑端无代码改动，沿用 1.1.2）

## 修的是什么现象

v1.2.3 之后仍然会复现：**从桌面图标或快捷开关磁贴多点几次应用，或者连续点截屏，就会断线重连**；有时连接数会变成 2～4 条，截屏偶发没反应。

## 根因：MainActivity 被叠成了多个实例

`MainActivity` 原来是 `launchMode=standard`，每次从桌面图标 / 磁贴点开都会在同一个任务里**再叠一个新实例**（真机上抓到同一个进程里 3 个 MainActivity 记录，都是 LAUNCHER intent）。**每个实例各自持有一个 `RemoteWsClient`**，于是进程里同时有 3～4 条 WebSocket：

- 电脑端对同一台遥控器是「踢旧保新」，几条连接互相顶掉，每次会话只能活 1.5～20 秒；
- 手机端日志同一时刻出现 4 条 `ws failure`（`Software caused connection abort` / `sent ping but didn't receive pong`）——每条都属于不同实例，这正是"多实例"的铁证；
- 被顶掉的那条收不到截屏/文件回包，表现为"点了没反应"。

v1.2.3 做的「建连单飞 + 代际号」只在**单个实例内部**有效，管不到跨实例的多条连接，所以还要补这一刀。

## 修改

- `AndroidManifest.xml`：`MainActivity` 加 **`android:launchMode="singleTask"`**，桌面图标 / 磁贴 / 最近任务多次点开一律复用同一实例。
- `MainActivity.onNewIntent()`：复用实例时顺带 `client.wakeUp()` 探一次活，让"点开就能用"不依赖上一次连接的残余状态。
- 其余逻辑不变（v1.2.3 的单连接、指数退避、4001 退让、回包补发都保留）。

## 验证（一加 13 / ColorOS 17 + Windows 11，真机）

| 场景 | 修复前 | 修复后 |
|---|---|---|
| MainActivity 实例数 | 3 | **1** |
| 反复点桌面图标 6 次 + 连点 6 次截屏 | 持续重连、连接数涨到 2～4 | **新增重连 0 / 踢旧 0 / 发送失败 0**，截屏 6 次全部成功 |
| 静置 40 秒 | 每隔几秒重连一次 | **0 次重连**，连接恒为 1 条 |

## 升级方式

覆盖安装即可，同 release 签名，绑定与 token 保留；电脑端沿用 1.1.2，不必重装（已装 1.1.2 的话）。
